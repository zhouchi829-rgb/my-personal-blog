个人博客网站开发实训报告

----------

1.1 项目背景

1.2 项目目标
- 开发一个具有完整前后端功能的个人博客系统
- 实现用户认证、文章管理、图片上传等核心功能
- 构建响应式界面，提供良好的用户体验
- 掌握Node.js、Express、SQLite等技术的实际应用

1.3 项目特点
- 技术栈全面：涵盖前端、后端、数据库全栈技术
- 功能完整：包含用户系统、文章管理、评论系统、图片画廊等模块
- 代码规范：遵循现代Web开发最佳实践
- 易于部署：使用轻量级技术栈，部署简单

4.1.2 技术实现
// JWT认证中间件
const authenticateToken = (req, res, next) => {
    const authHeader = req.headers['authorization'];
    const token = authHeader && authHeader.split(' ')[1];
    
    if (!token) return res.status(401).json({ error: '访问令牌缺失' });
    
    jwt.verify(token, JWT_SECRET, (err, user) => {
        if (err) return res.status(403).json({ error: '令牌无效' });
        req.user = user;
        next();
    });
};

// Multer文件上传配置
const upload = multer({
    storage: storage,
    limits: { fileSize: 2 * 1024 * 1024 }, // 2MB限制
    fileFilter: function (req, file, cb) {
        const allowedTypes = /jpeg|jpg|png|gif/;
        const extname = allowedTypes.test(path.extname(file.originalname).toLowerCase());
        const mimetype = allowedTypes.test(file.mimetype);
        
        if (mimetype && extname) {
            return cb(null, true);
        } else {
            cb(new Error('只允许上传图片文件（JPEG、JPG、PNG、GIF）'));
        }
    }
});

5.5 关键技术问题及解决方案

问题1：图片上传后页面刷新丢失
问题描述：在开发初期，用户上传的图片仅存储在前端JavaScript数组中，当页面刷新时，所有上传的图片都会消失。
根本原因：缺乏数据持久化机制，图片数据仅存在于浏览器内存中。
详细解决方案：
1. 数据库层面：创建专门的gallery_items表，包含作品标题、描述、图片URL、分类、标签、作者ID等字段
2. 后端层面：实现完整的图片上传API，包括文件验证、存储和数据库记录
3. 前端层面：修改上传逻辑，调用真实的后端API，并实现从数据库加载作品的功能
4. 文件存储：配置multer将上传的图片保存到public/uploads目录，使用唯一文件名防止冲突

问题2：用户认证令牌无效
问题描述：用户在上传图片时经常遇到"令牌无效"的错误提示。
根本原因：
1. 用户未登录或登录状态已过期
2. 前端未正确保存或传递JWT令牌
3. 令牌验证逻辑存在问题
详细解决方案：
1. 改进登录流程：在画廊页面添加明确的登录提示，当未登录用户尝试上传时，提示跳转到登录页面
2. 令牌管理优化：确保登录后正确将令牌保存到localStorage，并在所有需要认证的请求中自动添加Authorization头
3. 错误处理增强：在前端代码中添加详细的错误日志，帮助调试认证问题
4. 用户体验改进：在写文章页面添加检查，确保用户在使用图片上传功能时已登录

问题3：服务器无法启动
问题描述：用户报告页面无法打开，检查发现服务器未运行。
根本原因：
1. Node.js进程意外终止
2. 端口3000被其他程序占用
3. 项目依赖缺失或配置错误
详细解决方案：
1. 进程管理：使用正确的命令启动服务器：node "C:\Users\Lenovo\Desktop\my-personal-blog\server.js"
2. 端口检查：验证端口3000是否可用，如有冲突则更换端口
3. 依赖检查：确保所有npm依赖已正确安装
4. 错误处理：在服务器代码中添加更详细的启动错误提示

问题4：跨域访问问题
问题描述：前端在访问API时遇到跨域错误。
解决方案：在Express.js中配置CORS中间件，允许前端从不同源访问API。

问题5：数据库连接失败
问题描述：服务器启动时数据库连接失败。
解决方案：确保数据库文件存在且有正确的读写权限，添加数据库连接错误处理。

5.6 性能优化措施
1. 数据库优化：
   - 为常用查询字段（如author_id、category、status）添加索引
   - 使用连接查询减少数据库访问次数
   - 实现分页查询，避免一次性加载大量数据

2. 前端性能优化：
   - 压缩和合并CSS/JavaScript文件
   - 使用图片懒加载技术
   - 实现客户端缓存，减少重复请求

3. 服务器优化：
   - 使用HTTP压缩减少传输数据量
   - 配置适当的HTTP缓存头
   - 实现请求限流，防止恶意访问

4. 代码优化：
   - 使用异步编程避免阻塞
   - 实现错误边界，防止单点故障影响整体功能
   - 添加详细的日志记录，便于问题排查

5.7 测试与调试
在开发过程中，我采用了以下测试方法：
1. 单元测试：对关键函数和模块进行测试
2. 集成测试：测试API接口的完整功能
3. 端到端测试：模拟用户操作测试完整流程
4. 性能测试：测试系统在高负载下的表现

使用Chrome DevTools进行前端调试，使用Postman进行API测试，确保所有功能正常工作。
